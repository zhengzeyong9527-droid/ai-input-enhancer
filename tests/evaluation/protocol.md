# Prompt Optimizer A/B Evaluation Protocol

## Objective

Evaluate whether each prompt-optimization mode improves downstream task execution relative to the original prompt while preserving explicit user intent and constraints.

## Dataset

The frozen dataset contains 30 Chinese prompts generated by an independent test-set agent:

- 10 `faithful` cases
- 10 `developer` cases
- 10 `specification` cases

The test-set generator does not execute or evaluate any case.

## Arms

- **A / baseline:** the original prompt is given to the runner.
- **B / optimized:** the original prompt is transformed with the exact mode-specific optimizer system prompt from `src/host/prompt/`, then that optimized prompt is given to the runner.

The only intentional difference between A and B is the task prompt.

## Runner controls

Runner A and Runner B are independent child-agent calls launched concurrently. They receive identical execution instructions, a fresh per-case context, no workspace access, no tools, no memory from other cases, and the same output schema. They use the current session's default agent route without explicit model overrides. The harness does not expose temperature or top-p controls for child-agent calls; neither runner receives a route or parameter override.

## Optimization controls

B uses the repository's exact system text for each selected mode. Conversation context, workspace document context, continuous optimization, and fallback routing are disabled. This is a prompt-equivalent evaluation of the plugin's mode logic; it does not invoke the browser-bound plugin RPC.

## Blind evaluation

A separate evaluation child agent receives each original task, declared constraints, and randomized `candidate_1` / `candidate_2` outputs. It receives no A/B label, no optimizer output, and no runner provenance.

## Scoring

Each candidate is scored from 0 to 5 on:

- task success
- fidelity to explicit goals and constraints
- clarity and executability
- constraint adherence
- restraint from unsupported assumptions or scope expansion

The evaluator also records a winner (`A`, `B`, or `tie`) and binary flags for success, unsupported assumptions, scope expansion, and constraint violation.

## Limitations

This 30-case, single-session evaluation is directional evidence rather than a statistical proof. Its runners use the same available child-agent route, but the harness does not expose fixed sampling parameters. Results must not be generalized to all models, languages, contexts, or real production repositories.
